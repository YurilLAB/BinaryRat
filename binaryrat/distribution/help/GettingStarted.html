Getting started with BinaryRat

Open a binary

  1. Extract the archive. Launch binaryrat on Linux or binaryrat.bat on Windows.
  2. In the project window, use File → New Project to create a local project, or open an existing project.
  3. Use File → Import File and select your binary. To try the included sample, choose help/examples/example on Linux or help/examples/example.exe on Windows.
  4. Double-click the imported program. Accept the normal Ghidra analysis prompt, or dismiss it and choose Tools → BinaryRat → Analyze with Profile in CodeBrowser.

New workspaces include BinaryRat’s menu actions. In a customized workspace, add BinaryRat from File → Configure in CodeBrowser.

Inspect the sample

  1. Find measurement_area in the Symbol Tree and navigate into its code.
  2. Open Tools → BinaryRat → Inspect Selected Function for focused decompilation as you navigate. Use the panel’s refresh or cancel controls.
  3. When analysis finishes, use Recover Layout at Cursor with parameter 0. The dialog lists the function’s parameters and suggests a new report file.
  4. The evidence table opens when the report is saved. Double-click a row to jump to its instruction. Reopen a saved report later with Browse Layout Evidence.

The sample contains a structure with count, width and height fields. Its source is provided for reference.

Correct a call prototype

  1. With Inspect Selected Function open, select the call to measurement_bias inside measurement_area in the Listing.
  2. Choose Inspect Instruction P-code to see the operations for that instruction, with register names.
  3. Choose Override Call Prototype, review the signature and calling convention, and select Apply. The change applies to that call site. Use CodeBrowser’s Undo to revert it.
  4. Choose Override Call Prototype again to see the override and replace it. For an indirect call, the first suggestion comes from the decompiler’s view of the call’s arguments.
  5. Use Open Interactive Decompiler to open the selected function and address for token-level actions such as renaming, retyping, or splitting a variable.

Choose analysis depth

  • Quick triage defers debug information import, Function ID, signature inference, and PE RTTI where present.
  • Normal analysis uses the Program’s configured Ghidra analyzers.
  • Deeper recovery enables decompiler parameter inference and PE RTTI where available.

A profile applies to one analysis run. Ghidra schedules the work and controls cancellation, so completed analysis can remain in the Program.

Headless and version information

Use binaryrat-headless on Linux or binaryrat-headless.bat on Windows. Pass a project directory that already exists. The headless launcher runs the same extension without desktop configuration:

./binaryrat-headless /path/to/projects walkthrough -import help/examples/example -preScript BinaryRatProfile.java quick

Run binaryrat --version (or binaryrat.bat --version) for the packaged versions. VERSION.txt provides the same information. The archive includes a compatible JDK.

Optional Python tools

With Python 3.10 or later, install the BinaryRat wheel and the bundled PyGhidra dependencies into a virtual environment from the application directory:

python -m pip install --no-index --find-links python --find-links ghidra/Ghidra/Features/PyGhidra/pypkg/dist "binaryrat[live]"

Set JAVA_HOME_OVERRIDE to the full path to the bundled jdk directory. Use saved projects for scripting and supply the bundled Ghidra path:

binaryrat-decompile project.gpr /example measurement_area --install-dir ghidra
binaryrat-decompile project.gpr /example --list --match measurement --install-dir ghidra

Select a function by name or by any address inside it, as shown in CodeBrowser. Add --json for the result with its backend and cache status.
